## Why

单表双击打开与 SQL 查询结果两种入口的数据表格，分页与刷新位置、尺寸不一致，且无法在结果网格中直接修改单元格并提交或撤销；用户期望与常见桌面客户端（如 Navicat）一致：统一工具栏布局、可编辑后通过「执行/确认」与「取消」控制落库与回滚。

## What Changes

- **统一结果区工具栏布局**：单表标签页与 SQL 结果区采用同一套布局——**分页与刷新置于右上角**，视觉与交互以当前「双击表打开」的表格结果区样式为主。
- **分页与刷新控件尺寸**：分页与刷新按钮相对当前默认更**大**，便于点击；与紧凑全局规范的关系在规格中明确（见 Capabilities）。
- **单元格编辑**：在结果数据网格中**单击**进入可编辑状态，可修改单元格内容；编辑行为与现有长文本双击展开等逻辑需协调（见设计）。
- **左上角执行 / 取消（网格级）**：在表格结果区左上角增加**执行**与**取消**；**取消**丢弃未提交修改并恢复为加载时的原始值。**执行**在存在**全部脏行**时先打开 **Modal 预览**：展示将用于落库的**全部 UPDATE 语句**（每行脏数据对应语句，字符串与标识符按方言**正确转义**），正文可复制；Modal **右下角**提供**确定**（真正执行更新）与**取消**（关闭 Modal、不写库）。
- **后端**：提供按连接/方言生成与执行等价的 UPDATE（参数化执行 + 与预览一致的转义规则用于展示文本，具体见设计），错误时在 UI 反馈。

## Capabilities

### New Capabilities

- `studio-table-data-view`：涵盖统一工具栏、可编辑网格、**执行前 Modal 预览全部 UPDATE（可复制、转义正确）**、Modal 内确定/取消与网格级取消回滚。

### Modified Capabilities

- `frontend-compact-ui`：在「紧凑型全局视觉与按钮规范」上增加**数据结果区工具栏**的例外或变体说明（分页/刷新等控件允许使用较大尺寸，且与全局紧凑区并存），需通过 delta 规格补充。

## Impact

- **前端**：`frontend/` 中 `App.tsx` 及相关结果网格、SQL/表标签页布局与样式；可能新增或调整 CSS 变量/类名；与 `@glideapps/glide-data-grid` 的只读/编辑模式切换。
- **后端**：Go 侧数据库执行服务（或 Studio 相关 Service）增加或暴露「按主键更新行」的 API，经 Wails 绑定供前端调用；需考虑 SQL 注入防护、类型与主键列识别。
- **依赖**：无新增外部依赖的预期；复用现有 pgx/mysql 与 Wails 绑定模式。
