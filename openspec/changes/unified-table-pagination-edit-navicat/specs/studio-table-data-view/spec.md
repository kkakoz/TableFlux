## ADDED Requirements

### Requirement: Studio 数据结果区统一工具栏布局

在 Studio 工作台中，单表标签页与 SQL 查询结果区在展示二维结果数据时 SHALL 使用统一的工具栏布局：**分页控件与刷新控件位于结果区右上角**；**执行（确认）与取消控件位于结果区左上角**。整体视觉样式以单表（对象树打开表）结果区为基准，使两种入口在同一连接/会话下呈现一致。

#### Scenario: 单表与 SQL 结果工具栏位置一致

- **WHEN** 用户打开单表数据视图并查看结果区工具栏
- **THEN** 分页与刷新出现在右上角，执行与取消出现在左上角

#### Scenario: SQL 查询结果与单表布局一致

- **WHEN** 用户在 SQL 标签页执行查询并显示结果网格
- **THEN** 结果区工具栏控件分区与单表视图相同（左上执行/取消，右上分页/刷新），且样式与单表视图一致

### Requirement: 分页与刷新控件尺寸

数据结果区工具栏中的分页与刷新控件 SHALL 使用大于应用内默认紧凑小按钮的尺寸变体，以保证易于点击；具体像素或令牌由实现定义并可在样式中集中调整。

#### Scenario: 控件可点击性

- **WHEN** 用户使用鼠标操作分页或刷新
- **THEN** 控件的可点区域明显大于默认紧凑图标按钮，且视觉上可辨识为分页与刷新

### Requirement: 单元格单击编辑

在支持编辑的数据结果网格中，用户 SHALL 能够通过单击单元格进入编辑并修改单元格内容；修改在未确认前仅影响前端展示状态，不写入数据库。

#### Scenario: 编辑后未确认前可撤销

- **WHEN** 用户单击某单元格并修改内容且尚未点击执行
- **THEN** 该变更反映在网格中且用户可通过取消恢复为加载时的原始值

### Requirement: 执行与取消（Navicat 式确认/回滚）

数据结果区 SHALL 提供工具栏级**执行**与**取消**：**取消**丢弃未提交变更并将受影响的行恢复为本次加载数据时的原始内容。**执行**在存在未提交变更时 SHALL **先**打开预览 Modal，**不**在点击工具栏「执行」的瞬间写库。

#### Scenario: 网格取消恢复

- **WHEN** 用户修改单元格后点击工具栏「取消」
- **THEN** 所有未提交的修改被丢弃，相关单元格恢复为打开本页数据时的原始值

### Requirement: 执行前 Modal 预览全部 UPDATE

当存在一条或多条**脏行**时，用户点击工具栏「执行」SHALL 打开 Modal，Modal 内 SHALL 展示**全部**待提交行对应的 **UPDATE** 语句预览（每行脏数据至少对应一条语句或等价清晰分段）；展示文本 SHALL 支持用户**复制**（至少包括全选与系统复制）。Modal **右下角** SHALL 提供**确定**与**取消**：**确定**在关闭 Modal 前触发后端按主键执行上述更新；**取消**关闭 Modal 且**不**执行任何数据库更新。

#### Scenario: Modal 确定后落库

- **WHEN** 用户在预览 Modal 中点击右下角「确定」且后端成功
- **THEN** 系统对全部脏行执行主键定位的更新，并更新界面状态以反映成功提交（例如刷新当前页或合并返回数据）

#### Scenario: Modal 取消不写库

- **WHEN** 用户在预览 Modal 中点击右下角「取消」
- **THEN** Modal 关闭，数据库不发生变更，网格仍保留未提交的编辑状态

#### Scenario: 预览语句可复制

- **WHEN** 用户在预览 Modal 中选中文本或使用提供的复制能力
- **THEN** 剪贴板内容与 Modal 中展示的 UPDATE 文本一致

### Requirement: 预览 SQL 字符串与标识符转义

Modal 中展示的 UPDATE 文本 SHALL 按当前连接 **SQL 方言**（至少包括项目已支持的 PostgreSQL 与 MySQL）对**字符串字面量**与**标识符**进行正确转义或引用，使得展示语句在语义上与后端参数化执行所使用的值一致；包含单引号、反斜杠等边界字符时 MUST 在预览中可见且可安全复制到外部客户端执行（在权限与对象存在的前提下）。

#### Scenario: 含单引号的字符串在预览中正确转义

- **WHEN** 某单元格新值包含需转义的字符（例如单引号）
- **THEN** Modal 中对应 UPDATE 的字符串字面量按方言规则转义，不出现未闭合引号或错误拼接

#### Scenario: 执行失败提示

- **WHEN** 用户在 Modal 中确认执行后数据库返回错误（约束、类型、权限等）
- **THEN** 用户收到明确错误反馈，且未成功提交的网格编辑状态按产品约定保留或部分回滚（实现须一致并在界面说明）

### Requirement: 主键与可更新范围

执行更新时，系统 MUST 仅基于**主键列**定位待更新行；主键列集合 SHALL 来自表元数据或后端为结果集提供的可靠标注。对于无法确定主键或不允许安全更新的结果集，执行更新能力 MAY 被禁用，但工具栏布局与分页刷新仍 SHALL 与可编辑场景保持一致（除禁用态外）。

#### Scenario: 无主键时禁用执行

- **WHEN** 当前结果集无法确定主键列
- **THEN** 执行（确认）处于禁用状态或不可见，且用户不会误以为已落库
