## Context

Studio 工作台中，「对象树双击打开表」与「SQL 标签执行查询」都会在下方展示 `VirtualResultGrid`（或等价结果区），但工具栏（分页、刷新）位置与样式可能不一致；当前网格以展示与复制为主，单元格编辑与落库能力缺失。产品目标是对齐 Navicat 类体验：统一布局、可编辑、确认/撤销与按主键更新。

## Goals / Non-Goals

**Goals:**

- 单表与 SQL 结果两种入口共用**同一套结果区工具栏布局**：**左上**为执行（确认）与取消；**右上**为分页与刷新，且以当前表打开结果的样式为基准统一 SQL 侧。
- 分页与刷新控件在视觉上**明显大于**当前通用紧凑小按钮，仍保持可访问的最小点击区域。
- 支持**单击进入编辑**（在 glide-data-grid 中通过 `readonly` 与 `onCellEdited` 或 overlay 编辑协调实现），未提交前变更仅存于前端状态。
- **执行（两阶段）**：用户点击工具栏**执行**时，先打开 **Modal**，列出**全部脏行**对应的 **UPDATE** 预览（可多段文本）；预览区内容**可复制**；**右下角「确定」**再调用后端按主键执行更新；**右下角「取消」**仅关闭 Modal，不写库。**WHERE** 仅使用主键列。预览中的**字符串字面量** MUST 按当前连接方言做**正确转义**（与真实执行语义一致）。
- **取消（网格级）**：工具栏**取消**丢弃未提交修改，恢复为本次加载的原始行快照（与 Modal 内「取消」区分）。

**Non-Goals:**

- INSERT/DELETE、跨表批量、外键级联、事务内多语句编排（本变更仅覆盖**多行脏数据的主键 UPDATE 预览与执行**）。
- 无唯一主键或复合主键部分为 NULL 时的复杂策略（可在实现阶段以明确错误提示处理）。
- 与 Excel 完全一致的键盘导航与填充柄。

## Decisions

1. **工具栏结构**  
   - 采用 **Flex 两行或单行**：左侧组（执行、取消），右侧组（分页、刷新），与「表标签」现有 DOM 结构对齐后抽成共享组件或共享 JSX 片段，避免 SQL/表两处分叉。  
   - **Rationale**：减少回归面，保证「以双击表样式为主」的可视一致性。

2. **编辑模型**  
   - 使用 glide-data-grid 的 **`readonly: false`**（或按列 `readonly`）+ **`onCellEdited`**；本地维护 `Map<rowId, Record<col, value>>` 或行级 dirty 与 `originalRow` 快照。  
   - **主键列**：从表模式元数据（表标签）或从结果列名集合中与后端约定（如 `ExecuteSQL` 返回 `primaryKeyColumns`）获取；若仅 SQL 结果无法可靠识别主键，则 SQL 结果区可禁用「执行」或仅允许在「表上下文明确」时启用（**Open Question** 见下）。  
   - **Alternatives**：弹窗表单编辑整行——与「单击格编辑」需求不符，否决。

3. **后端 API 与预览 SQL 一致性**  
   - **执行**：在现有 Database/Studio Service 中新增批量能力，例如：`UpdateRowsByPK(ctx, req)`，一次提交**全部脏行**；内部仍用**参数化**执行。  
   - **预览文本**：提供 `PreviewUpdateStatements`（或与执行共用同一构建器）按方言生成**可展示的 UPDATE 字符串**；生成逻辑与绑定值 MUST 同源，确保预览中的字面量**转义**（单引号、反斜杠、Unicode 等按 **PostgreSQL / MySQL** 规则）与执行一致。表名/列名使用方言规定的**标识符引用**与转义。  
   - **Rationale**：用户复制预览即得到可在外部工具试跑的语句（在权限允许前提下）；执行侧仍避免注入。若预览仅用于展示，亦不得与参数化执行的值语义冲突。

4. **SQL 结果页是否可编辑**  
   - **默认**：若当前结果可映射到单表且能解析主键（例如来自带表上下文的查询或后端标注），则允许与表标签一致；否则只读并灰化执行。  
   - **Rationale**：满足「统一分页到右上」与「单击编辑」的 UI 统一，同时避免任意手写 SQL 无法安全 UPDATE 的风险。

5. **与紧凑 UI 规范的关系**  
   - 在 `frontend-compact-ui` 规格中 **ADDED** 一条：数据结果区工具栏分页/刷新使用「较大」尺寸变体，不强制套用全局小按钮规范。  
   - **Rationale**：与用户需求一致且不推翻全局紧凑密度。

6. **执行前 Modal 与预览复制**  
   - 工具栏「执行」**不立即写库**：打开 Modal，展示**全部脏行**对应的 UPDATE 预览（建议按行分隔、可滚动）。  
   - Modal **右下角**放置**确定**（提交执行）与**取消**（关闭且不写库）；预览区域支持全选与复制，可选「复制全部」辅助按钮。  
   - **Rationale**：与 Navicat「先看 SQL 再提交」习惯一致；复制出的文本必须转义正确，便于审计与外部执行。

## Risks / Trade-offs

- **[Risk] 任意 SQL 结果无主键** → 禁用执行或仅展示提示；表标签路径优先完整体验。  
- **[Risk] 并发修改覆盖** → 首期可采用「读后直接 UPDATE」；可选在后续加入 `WHERE` 中校验非主键列版本号（非本变更必做）。  
- **[Risk] 大对象列编辑** → 与现有长文本弹窗协同：编辑大字段时可仍用弹窗，网格内显示摘要。  
- **[Trade-off] 单击编辑 vs 双击打开详情** → 需调整 `VirtualResultGrid` 中「同格双击打开详情」的判定，避免与单击冲突（例如详情仍用双击或专用图标）。

## Migration Plan

- 纯功能发布：无数据迁移。  
- 回滚：关闭编辑（`readonly`）与隐藏执行/取消即可恢复只读行为。

## Open Questions

- SQL 结果无主键时，产品是否接受「仅只读 + 统一工具栏」？（建议：接受。）

**已决**：执行范围固定为**提交全部脏行**；落库前必须经过 **Modal 预览**，**右下角确定**后执行；预览语句可复制，字符串转义按方言正确处理。
