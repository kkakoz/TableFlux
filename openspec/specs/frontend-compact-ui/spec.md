# frontend-compact-ui

## Requirements

### Requirement: 紧凑型全局视觉密度

前端主界面 SHALL 采用统一的紧凑视觉密度：列表、表单与工具区域的垂直间距 SHALL 小于或等于变更实施时在根样式或设计令牌中定义的紧凑基准，且主要工作区（数据网格、编辑器）SHALL 优先保留可视区域，避免被过大留白或过大控件挤压。

#### Scenario: 设置与常用面板密度一致

- **WHEN** 用户打开设置及至少一个其他主要功能面板（与实现时选定的参考页面一致）
- **THEN** 这些面板在区块间距、分组标题与内容之间的间距上呈现一致的紧凑尺度，无明显一种页面明显更「松」或更「紧」的对比

### Requirement: 按钮与主要可操作控件的小尺寸规范

系统 SHALL 为默认按钮、工具栏按钮及图标按钮定义统一的小尺寸规范（高度、水平内边距、圆角若适用 SHALL 来自同一套令牌或类名）。新增或修改的此类控件 MUST 使用该规范；既有控件在变更范围内 SHOULD 被迁移到该规范。规范 SHALL 在可访问性上保持合理的最小可点击区域（不低于项目在实施阶段书面记录的最小值，且符合桌面端惯例）。

#### Scenario: 同类按钮外观一致

- **WHEN** 用户在同一视图内看到多个属于同一语义层级的主按钮或次要按钮
- **THEN** 这些按钮在高度与内边距上一致，且整体小于变更前未统一时的默认大块样式（以变更基线截图为参照）

### Requirement: 样式约定可发现且可维护

项目 SHALL 在 Cursor 规则（或项目约定的同等规则文件）中包含「前端紧凑 UI」章节，说明：紧凑布局与按钮尺寸应使用的 CSS 变量或类名命名模式、修改全局样式时的注意点、以及禁止随意新增互斥的按钮尺寸常量。实现代码中的令牌或根变量 MUST 与规则中的命名指向一致，避免文档与实现两套体系。

#### Scenario: 规则与代码对齐

- **WHEN** 贡献者阅读 Cursor 规则中的前端样式章节并查看 `frontend` 中的根样式或令牌定义
- **THEN** 二者对「紧凑」所依赖的变量或类名描述一致，能够据此新增符合规范的 UI 而无需猜测魔法数
